# Privacy policy

Effective date: 24 August 2026

The 5th Ledger is a skills-only plugin. It has no publisher-operated server, account system, authentication, telemetry, advertising, analytics, background runtime, or data store. The publisher does not receive plugin prompts, files, command output, or conversation content through the plugin.

## Data processed in ChatGPT or Codex

When a user invokes a skill, the host product may process the text, files, repository state, or tool results the user chooses to provide. That processing occurs within the user's ChatGPT or Codex environment under the host provider's controls and policies. The 5th Ledger instructions encourage data minimization and keep project-owned permissions and privacy rules in force; they do not create another data transfer to the publisher.

Users should not provide passwords, API keys, authentication secrets, payment-card data, government identifiers, protected health information, or other information that is unnecessary for the governance task.

## Data received through public project channels

If a user voluntarily opens a GitHub issue, pull request, discussion, or security advisory, the publisher may receive the information submitted there.

The categories of personal data, purposes, recipients, retention, and controls for
those voluntary channels are:

| Category | Purpose | Recipients | Retention | User control |
| --- | --- | --- | --- | --- |
| GitHub account and contribution metadata | Route, review, and respond to the request | The publisher and GitHub under GitHub's service terms | For as long as the public record or private advisory is needed for project maintenance, subject to GitHub controls | Edit or delete content where GitHub permits, close the request, or contact the maintainer through the same channel |
| User-supplied issue, pull-request, or advisory content | Diagnose support or security reports and maintain the project | The publisher; public GitHub visitors for public records; invited collaborators for private advisories | Public records normally remain as project history; sensitive private advisory material is retained only as needed for remediation and audit | Do not submit unnecessary data; edit or delete where GitHub permits; request minimization through the same record |

The publisher does not sell this information, use it for advertising, or use it for behavioral profiling.

## Local and adopter-owned evidence

The plugin may guide a user to create local project records or run user-authorized commands. Those records remain in the location and under the access controls chosen by the user or their project. The publisher cannot access or delete them. Users control retention through their own filesystem, repository, workspace, and provider policies.

## Changes

Material changes to this policy will be recorded in the repository before a revised plugin version is submitted for review. The effective date will be updated when the policy changes.

## Contact and controls

Use the public-safe route in [SUPPORT.md](SUPPORT.md) for privacy questions. Use the private route in [SECURITY.md](SECURITY.md) for sensitive security or privacy reports. Do not post sensitive details publicly.
